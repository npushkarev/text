# Перенос текущих исходников cs_doc в as_doc

Скрипт `bitbucket-copy-sources.py` запускается в терминале машины с доступом к внутреннему Bitbucket.
Нужны Python 3.6+ и git. Дополнительные Python-пакеты не нужны.

## Запуск

Из каталога с этим скриптом. Проверка и план, без изменений в Bitbucket:

```sh
python3 bitbucket-copy-sources.py --user '<логин_Bitbucket>'
```

Перенос:

```sh
python3 bitbucket-copy-sources.py --user '<логин_Bitbucket>' --apply
```

Замените `<логин_Bitbucket>` своим логином. Пароль для REST запрашивается скрыто.
Git использует ваш credential helper либо отдельно запрашивает логин и пароль.
Учётная запись должна читать `cs_doc`, создавать репозитории в СУРА2 и писать в `as_doc`.

Git должен иметь настроенные имя и email автора. Вместо изменения git config можно передать:

```sh
python3 bitbucket-copy-sources.py --user '<логин_Bitbucket>' \
  --git-name '<имя_автора>' --git-email '<email_автора>' --apply
```

## Что получится

- Проект СУРА2 (`SU2`).
- Источник `cs_doc`, его ветка по умолчанию на момент клонирования.
- Новый `as_doc` или уже существующий полностью пустой `as_doc`.
- Все файлы выбранного коммита, включая скрытые и бинарные. Права исполняемых файлов и симлинки сохраняются.
- Один новый начальный коммит без родителей. История `cs_doc` на сервер назначения не отправляется.
- Ветки `master` и `develop` от этого коммита. По умолчанию `develop`.

Две ветки оставлены как в предыдущем скрипте создания репозитория. Для другой пары:

```sh
python3 bitbucket-copy-sources.py --user '<логин_Bitbucket>' \
  --first-branch '<первая_ветка>' --second-branch '<вторая_ветка>' \
  --default-branch '<одна_из_двух_веток>' --apply
```

Для выбора конкретной исходной ветки добавьте `--source-branch '<ветка_cs_doc>'`.
Скрипт печатает SHA исходного коммита. Проверка и перенос в разных запусках могут взять разные коммиты, если источник изменился.

Версию `0.1.0` скрипт не выставляет. Файлы копируются без изменений.
Сборочную линию TeamCity он не создаёт. Эти части заявки выполняются отдельно.

## Ограничения и ошибки

Непустой `as_doc` не меняется. Скрипт не делает force push и не удаляет репозитории.
Git LFS и submodules требуют отдельного переноса. При их обнаружении скрипт останавливается до изменений на сервере.

Push двух веток атомарный. Если сервер не поддерживает `--atomic`, скрипт остановится без запасного неатомарного push.
Если ошибка произошла после push, исходники уже могут быть в `as_doc`. Повторный запуск остановится на проверке непустого репозитория.
Рабочий каталог печатается при запуске и сохраняется для диагностики. В нём есть локальная копия истории `cs_doc`.
При ошибке выбора Default branch выставьте её через Repository settings после проверки результата.

При ошибке сертификата установите доверенный корпоративный CA на машине. Проверка TLS не отключается.
Если внутренняя установка доступна только по HTTP, явно задайте `--bitbucket http://bitbucket.inc.elara.local`.
HTTP не шифрует пароль.

## Локальные проверки

```sh
python3 -m unittest discover -s tests -p 'test_bitbucket_copy_sources.py' -v
```

Тесты используют временные локальные Git-репозитории и имитацию Bitbucket REST.
Они не подключаются к внутреннему серверу и не проверяют его права, сертификаты и настройки Git.
