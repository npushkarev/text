# Создание репозитория в Bitbucket

Скрипт: `bitbucket-create-repo-f12.js`. Для внутреннего Bitbucket Server, не Bitbucket Cloud.

## Что сделать

1. Откройте Bitbucket под учётной записью с правом создания репозиториев в нужном проекте.
2. Откройте проект СУРА2. Его ключ в Bitbucket: `SU2`, адрес: `/projects/SU2/`.
3. Откройте скрипт и заполните настройки в начале:

   ```js
   const APPLY = false;
   const PROJECT = "SU2";
   const REPO = "<имя_нового_репозитория>";
   const BRANCHES = ["master", "develop"];
   const DEFAULT_BRANCH = "develop";
   ```

   Замените `<имя_нового_репозитория>` своим именем. Используйте строчные латинские буквы, цифры, `.`, `_`, `-`.
   `PROJECT = "SU2"` задаёт проект СУРА2 независимо от открытой страницы.
   `master` и `develop` взяты из существующего `init_repos.sh`. Можно задать другую пару.
   `DEFAULT_BRANCH` должен совпадать с одним из двух имён.

4. Нажмите F12, откройте Console, вставьте весь скрипт и нажмите Enter.
5. Проверьте таблицу плана. При `APPLY = false` сервер не изменяется.
6. Поставьте `APPLY = true`, снова вставьте весь скрипт. Подтвердите создание во всплывающем окне.
7. Дождитесь `ГОТОВО` и откройте напечатанную ссылку.

## Результат

- Новый репозиторий в проекте СУРА2 (`SU2`).
- Первый коммит с `README.md`. Автором будет текущая учётная запись Bitbucket.
- Ровно две ветки от этого коммита.
- Выбранная ветка по умолчанию.

Отдельный токен не нужен. Скрипт использует текущую браузерную сессию.
Существующий репозиторий, даже пустой, скрипт не меняет. Force push и удаления нет.

## Если произошла ошибка

При ошибке до создания репозитория изменений нет. После сообщения `CREATED` репозиторий уже существует.
Скрипт сообщает незавершённый этап и оставляет репозиторий на сервере. Повторный запуск остановится на проверке существования.

Если сервер не поддерживает первый коммит через `PUT .../browse/README.md`, используйте обычный git:

```sh
git clone '<HTTP clone URL из кнопки Clone>' '<локальный_каталог>'
cd '<локальный_каталог>'
git ls-remote --heads --tags origin
```

Продолжайте только если последняя команда завершилась успешно и не вывела ни одной ссылки.
При уже созданных ветках сначала проверьте их в Bitbucket. Не переписывайте историю.

Для полностью пустого репозитория:

```sh
git checkout -b '<первая_ветка>'
printf '# %s\n' '<имя_репозитория>' > README.md
git add README.md
git commit -m 'Initial commit'
git branch '<вторая_ветка>'
git push origin '<первая_ветка>' '<вторая_ветка>'
```

Замените все значения в угловых скобках. Git должен иметь настроенные `user.name` и `user.email`.
Выберите Default branch в Repository settings. URL для clone берите из кнопки Clone, а не из адреса `/projects/.../repos/...`.

## Проверки

Локальная проверка синтаксиса и тесты с имитацией REST:

```sh
node --check bitbucket-create-repo-f12.js
node --test tests/test-bitbucket-create-repo.cjs
```

Эти проверки не подтверждают совместимость с конкретной установленной версией Bitbucket.
Первый коммит через REST нужно проверить на сервере. Скрипт не запускается там автоматически.
