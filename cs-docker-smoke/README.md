# Пробный запуск автотестов КС в Docker

Скрипт `run.sh` проверяет, можно ли гонять тесты `SU2/cs_auto_test` против КС в Docker
без железа: без `--privileged`, `--network host`, USB и COM-портов.
Это первый шаг перед профилем для tdc-runner.

## Что делает

1. Скачивает образ КС и образ python из ProGet.
2. Собирает образ тестов: python + пакеты из `requirements.txt`.
3. Создаёт отдельную сеть и запускает КС с именем `cs`. Сеть внутренняя: наружу выхода нет.
4. Ждёт, пока КС откроет порты (`CS_PORTS`), или 20 секунд, если порты не заданы.
5. Запускает pytest с `--device-ip=cs`. Тесты ходят в КС по имени, без IP.
6. Сохраняет логи и отчёты, удаляет контейнер, сеть и образ тестов.

Репозиторий с тестами не меняется: тесты работают на копии.

## Что нужно

- Linux x64 с Docker. Пользователь в группе `docker`.
- Доступ к `proget.inc.elara.local` и `bitbucket.inc.elara.local`.
- `docker login proget.inc.elara.local`.
- Тег КС: ProGet > main > `library/cs_product` > All Tags, самый новый.
- Образ python: ProGet > main > `library/python`, версия под тесты.
- Если pip не видит пакеты: адрес PyPI-фида ProGet.

## Как запустить

```sh
git clone https://github.com/npushkarev/text.git
cd text/cs-docker-smoke

CS_TAG='<тег КС>' \
PY_IMAGE='proget.inc.elara.local/main/library/python:<версия>' \
./run.sh
```

Без аргумента скрипт сам клонирует `cs_auto_test` (ветка `develop`) в текущий каталог.
Уже есть клон: передайте путь `./run.sh /путь/к/cs_auto_test`.

## Настройки

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `CS_TAG` | нет, обязательно | тег образа КС |
| `PY_IMAGE` | нет, обязательно | образ python для тестов |
| `CS_IMAGE` | `proget.inc.elara.local/main/library/cs_product` | путь к образу КС |
| `PIP_INDEX_URL` | пусто | PyPI-фид ProGet, например `https://proget.inc.elara.local/pypi/<фид>/simple` |
| `PYTEST_K` | `test_ip` | какие тесты запускать, как `pytest -k` |
| `PYTEST_ARGS` | пусто | дополнительные аргументы pytest |
| `CS_PORTS` | пусто | порты КС через запятую, например `4840,502`. Скрипт ждёт, пока они откроются |
| `WAIT_SECONDS` | `120` | сколько ждать порты |
| `INTERNAL` | `1` | `0`: дать сети выход наружу, если тестам он нужен |
| `GEN_PROTO` | `0` | `1`: перед тестами выполнить `grpc_tools.protoc` из README репозитория |
| `KEEP` | `0` | `1`: не удалять контейнер КС и сеть, чтобы посмотреть руками |
| `REPO_BRANCH` | `develop` | ветка `cs_auto_test` для клонирования |
| `OUT` | `./cs-smoke-out` | куда сложить результаты |

## Результат

В каталоге `cs-smoke-out/`:

| Файл | Что внутри |
|---|---|
| `cs.log` | лог контейнера КС |
| `cs.state` | состояние КС в конце: работает или упала, код выхода, OOM |
| `build.log` | сборка образа тестов (pip install) |
| `pytest.log` | вывод pytest |
| `junit.xml` | отчёт для TeamCity |
| `report.html` | отчёт pytest-html, если пакет есть в `requirements.txt` |

## Что значит результат

| Сообщение | Причина | Что делать |
|---|---|---|
| `ТЕСТЫ ПРОШЛИ` | КС работает без железа, тесты её видят | Можно делать профиль для tdc-runner |
| `не скачать КС` | Нет входа в ProGet или неверный тег | `docker login proget.inc.elara.local`, проверить тег |
| `pip install не прошёл` | Нет доступа к пакетам | Задать `PIP_INDEX_URL`, проверить, что в фиде есть все пакеты |
| `КС остановилась` | КС не стартует без железа или прав | Смотреть `cs.log`. Если нужен USB, COM или privileged: вопрос к лиду |
| `порты ... не открылись` | Неверные порты или КС стартует дольше | Уточнить порты у Машкова, увеличить `WAIT_SECONDS` |
| `ошибка аргументов` | В ветке нет опции `--device-ip` | Проверить `conftest.py`, взять ветку, где она есть |
| `ни один тест не выбран` | `PYTEST_K` не совпал с именами тестов | Задать другой `PYTEST_K` |
| `есть упавшие тесты` | Тест упал | Смотреть `pytest.log`. Ошибка разбора `cs` как IP: Машкову разрешить имя хоста |

Код выхода скрипта: код pytest (`0` значит всё прошло), `2` значит ошибка до запуска тестов.
