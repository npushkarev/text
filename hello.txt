Кеш в Conan — коротко
  
  Что хранит Conan

  ~/.conan2/             ← Conan home (всё что Conan знает)
  ├── p/                 ← packages — ВЕС (95% места)
  │   └── <ref-hash>/    ← один пакет
  │       ├── e/         ← exported conanfile
  │       ├── s/src/     ← распакованные исходники
  │       ├── b/         ← build folder (объектники)
  │       └── p/         ← готовый install (lib/, include/)
  ├── c/                 ← SQLite metadata
  ├── profiles/          ← Conan-профили
  └── global.conf        ← глобальные настройки

  Размер на полную grpc-сборку: 5-15 GB.

  Где это можно положить — 3 варианта

  1. Дефолт (ничего не настраивать)
  
  ~/.conan2/             ← на $HOME
  Просто. Минус: $HOME маленький → закончится место.

  2. Перенести всё на другой диск

  export CONAN_HOME=/mnt/big-disk/conan2
  Один env-var, переезжает всё. Самое простое решение.
  
  3. Разделить: метаданные на SSD, тяжёлые пакеты на NFS/HDD

  В ~/.conan2/global.conf:
  core.cache:storage_path=/mnt/big-disk/conan-pkgs
  Profiles/settings остаются на SSD (быстро), пакеты на медленном большом.

  На TC агентах — где хранить

  Linux-агент (Docker)

  # В TC build step:
  docker run \
      -v conan-cache-<arch>:/root/.conan2 \   ← cache в Docker volume per-agent
      grpc-tc-mirror \
      ./test-astra/run_grpc_1601_upstream.sh

  ┌────────────────────────────────────────┬───────────────────────────────────────────────┐
  │                Вариант                 │                   Что даёт                    │
  ├────────────────────────────────────────┼───────────────────────────────────────────────┤
  │ Named volume (текущее)                 │ Cache переживает container restart. Прост.    │
  ├────────────────────────────────────────┼───────────────────────────────────────────────┤
  │ Bind mount -v /opt/cache:/root/.conan2 │ Видно с хоста, можно бэкапить.                │
  ├────────────────────────────────────────┼───────────────────────────────────────────────┤
  │ tmpfs --tmpfs /root/.conan2            │ RAM-cache, быстро, но всё с нуля каждый билд. │
  └────────────────────────────────────────┴───────────────────────────────────────────────┘

  Windows-агент (натив)
  
  set CONAN_HOME=D:\conan-cache
  conan create ...
  D:\ — обычно большой диск; C:\Users\... — system disk, мал.
  
  Общий кеш на ВСЕ TC-агенты через ProGet

  Лучшая стратегия для CI с многих агентов:

  # 1. Однократно на агенте: добавить ProGet как Conan remote
  conan remote add elara-proget https://proget.inc.elara.local/api/v2/repository/conan/

  # 2. После сборки: пушим бинари в ProGet
  conan upload "grpc/1.60.1@" --remote=elara-proget --all --confirm

  # 3. На любом другом агенте: тянем готовое
  conan install --requires=grpc/1.60.1 -r=elara-proget --build=never

  Это даёт: «собрал раз — используют все агенты». Локальный cache у каждого агента остаётся маленьким (просто скачанное из ProGet).

  Source-tarballs (<pkg>/src/*.tar.gz)

  Сейчас в git-репо рядом с recipes. Если git клон становится тяжёлым (146 MB только grpc):

  ┌──────────────────────────┬────────────────────────────────────────────────────────────────────────────┐
  │         Вариант          │                                    Как                                     │
  ├──────────────────────────┼────────────────────────────────────────────────────────────────────────────┤
  │ Git LFS для src/*.tar.gz │ Tarball'ы тянутся on-demand, не при git clone                              │
  ├──────────────────────────┼────────────────────────────────────────────────────────────────────────────┤
  │ Симлинк на NFS           │ ln -s /mnt/sources/grpc grpc/src                                           │
  ├──────────────────────────┼────────────────────────────────────────────────────────────────────────────┤
  │ Asset feed на ProGet     │ Запушить tarball'ы туда, патчить _offline_source_archive чтобы wget оттуда │
  └──────────────────────────┴────────────────────────────────────────────────────────────────────────────┘

  Полезные команды
  
  # Где сейчас Conan home?
  conan config home

  # Сколько занимает
  du -sh ~/.conan2/p/        # heavy packages
  du -sh ~/.conan2/          # всё

  # Сменить локацию (для текущей сессии)
  export CONAN_HOME=/mnt/big/conan
  mkdir -p "$CONAN_HOME"

  # Очистить
  conan cache clean "*"           # все пакеты
  conan cache clean "grpc/*"      # только grpc
  conan remove --confirm "*"      # снести cache entirely

  TL;DR
  
  1. Conan кэш = ~/.conan2/, всё внутри
  2. Перенести = export CONAN_HOME=/новый/путь
  3. На TC = Docker volume per-agent + ProGet как общий бинарный cache
  4. Sources = в git репо <pkg>/src/*.tar.gz пока места хватает
