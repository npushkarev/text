  1. Recipe-директории (8 шт) — суть миграции

  Каждый из этих каталогов — рецепт сборки одной third-party библиотеки. Структура одинаковая (canonical conan-center pattern + 2 наших edit'а):

  <pkg>/
  ├── conanfile.py            Recipe — Python-класс, описывает как собрать пакет:
  │                           options/requires/generate/build/package/package_info.
  │                           Зеркало из conan-center-index + offline-source
  │                           helper (2 локальных edit'а: exports_sources="src/*.tar.gz"
  │                           + _offline_source_archive() в source()).
  ├── conandata.yml           Метаданные: URLs/sha256 upstream-тарболлов +
  │                           регистрация .patch-файлов по версиям. Upstream-as-is.
  ├── src/<ver>.tar.gz        Offline-копия upstream-исходников. Нужна потому
  │                           что dev-VM/CI работают на closed-network — нет
  │                           доступа к github.com.
  ├── patches/                Локальные .patch файлы (unified diff) поверх
  │                           upstream. Применяются авто через apply_conandata_patches.
  └── test_package/           Conan smoke-тест: минимальный потребитель,
                              гоняется автоматом в `conan create`.

  Наши 8 recipes (= 8 каталогов в корне):
  - zlib/ — компрессия
  - gtest/ — Google Test
  - abseil/ — Abseil C++ utility libs
  - c-ares/ — async DNS resolver 
  - re2/ — regex library
  - protobuf/ — Protocol Buffers
  - openssl/ (3.x) и openssl-1x/ (1.1.x — для legacy compat с grpc 1.60)
  - grpc/ — собственно grpc; расширенный доп.файлами (см. ниже)

  2. extensions/deployers/legacy_nupkg.py — ядро migration-специфики

  Это наш custom deployer. Без него миграция не имела бы смысла — он берёт обычный conan-output (lib/, include/ в ~/.conan2/p/...) и переупаковывает в .nupkg-формат,
   байт-совместимый с legacy TeamCity артефактами.

  Что делает:
  - Имя файла: <legacy_name>.<os>.<compiler_short>.<linkage>.<arch_short>.<version>.nupkg
  - Внутренняя структура: lib/native/<lin-gcc84-static-x86_64>/, build/native/*.targets, .nuspec, CMakeLists.var
  - LEGACY_NAME_MAP: маппит conan-имя → legacy CI имя (gtest → googletest, c-ares → cares)
  - _short_compiler / _arch_short / _resolve_arch_short: маппят conan-settings в коротки CI-нотации (gcc 8.4 → gcc84, armv7hf → arm, +linaro суффикс если cross)
  - Coarse-aggregation для abseil (21 крупная .a вместо 150 мелких)
  - Alias-симлинки (libprotolib.a → libprotoc.a, libzlib.a → libz.a)
  - Proto-mirror для protobuf (копия *.proto в отдельный proto/-слой)
  
  3. profiles/ — Conan-профили (host & build платформ)

  profiles/
  ├── astra-gcc                       # host=build на dev-VM (Astra 1.8 gcc 8.4 native)
  ├── lin-gcc84-x86_64                # x86_64 native build (Docker mirror)
  ├── lin-gcc84-i686                  # 32-bit x86 (multilib в той же x86_64 image)
  ├── lin-gcc75-arm-linaro            # armv7hf cross (linaro 7.5)
  ├── lin-gcc-aarch64-linaro          # arm64 cross (linaro 7.5)
  ├── linux-gcc / linux-gcc-debug     # generic linux profiles (early POC)
  ├── win-v142-x64 / win-v142-x86     # Windows MSVC 2019 (vc142)
  ├── win-v143-x64                    # Windows MSVC 2022 (vc143)
  ├── windows-msvc / windows-msvc-debug
  └── toolchains/
      ├── linaro-arm.cmake            # CMAKE_TOOLCHAIN_FILE для armv7hf cross
      └── linaro-aarch64.cmake        # ... для aarch64 cross
                                      # Содержат -fuse-ld=gold workaround
                                      # под linaro 7.5 binutils 2.32 баг

  Профайл = pinned compiler, compiler.version, compiler.libcxx, arch, os, build_type + [buildenv] + [conf]. Conan читает это в pr:h=.../pr:b=....

  4. Offline-сборка (packages/, packages-linux/, src/*.tar.gz)

  На closed-network нет доступа к pypi/github. Migration положила всё локально:
  - packages-linux/conan-2.27.1.tar.gz + все её транзитивные зависимости (.tar.gz) — pip wheels Conan'а для Linux
  - packages/ — то же для Windows (.whl) 
  - packages-linux/cpython-3.11.10+...x86_64-linux-gnu.tar.gz — standalone Python 3.11 (Debian Stretch system python слишком стар для Conan 2)
  - <pkg>/src/<ver>.tar.gz — upstream-источники каждой библиотеки (тарболлы из github archive) 
  
  conanfile.py::source() для всех 8 recipes имеет helper _offline_source_archive() — он матчит filename из conandata.yml URL в src/ и распаковывает оттуда вместо
  wget.
