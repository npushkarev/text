Куда класть upstream-источники (<pkg>/src/*.tar.gz) — коротко
  
  Что это вообще

  Tarball'ы с github (v1.60.1.tar.gz, etc.) — нужны для offline-сборки на closed-network. Conan по умолчанию делает wget из conandata.yml URL → на закрытой сети
  падает. Наш _offline_source_archive() берёт их локально.

  Что наш deployer делает чтобы legacy compat сохранить
  
  1. Имя файла:     LEGACY_NAME_MAP + _short_compiler + _arch_short
  2. Версия:        LEGACY_VERSION_MAP + LEGACY_NUPKG_VERSION_SUFFIX
  3. Slot-tag:      "shared" всегда (env LEGACY_NUPKG_LINKAGE override)
  4. Структура:     lib/native/<suffix>/ — точно так же
  5. Aliases:       libz.a → libzlib.a, libprotoc.a → libprotolib.a
  6. abseil:        21 крупный .a из legacy-coarse (вместо 150 мелких)
  7. proto:         *.proto зеркалится в отдельный proto/ слой
  8. CMakeLists.var: _dependencies с legacy-именами+версиями
  9. .nuspec:       <dependencies> с тем же slot+arch+suffix

  TL;DR по legacy

  - Что заменяем: TC-конфиги GR113/GR121/GR122/GR120 + ручные shell-build-скрипты
  - Что НЕ ломаем: формат .nupkg, имена, slot-теги, структуру внутри. Downstream не должен ничего заметить.
  - Ключевой принцип: наш .nupkg подменяет старый byte-compatible, через ProGet через .1 суффикс (coexistence) или прямой replace (final cutover — решение лида)

⏺ legacy_nupkg.py — скрипт для упаковки в legacy .nupkg

  Что это в одной фразе

  Custom Conan deployer, который берёт обычный Conan-output из кэша и упаковывает его в .nupkg-формат, совместимый со старыми TeamCity-артефактами.

  Где живёт
  
  extensions/deployers/legacy_nupkg.py    ~700 строк

  Что делает (одной картинкой)

  ~/.conan2/p/<pkghash>/p/             ← готовый Conan-install
    lib/, include/, share/
              │
              │  conan install ... --deployer=legacy_nupkg.py
              ▼
  output/<legacy-name>.lin.gcc84.shared.x86_64.1.60.1.nupkg
    ├── lib/native/lin-gcc84-shared-x86_64/      ← Release .a
    ├── lib/native/lin-gcc84-shared-x86_64-d/    ← Debug .a
    ├── include/
    ├── proto/                                    ← только для protobuf
    ├── build/native/*.targets                    ← NuGet MSBuild stub
    ├── CMakeLists.var                            ← deps для Elara resolver
    └── *.nuspec                                  ← NuGet metadata

  Как запустить

  # Шаг 1: Release+Debug должны быть в Conan-cache
  conan create grpc/ --version=1.60.1 ... -s build_type=Release --build=missing
  conan create grpc/ --version=1.60.1 ... -s build_type=Debug --build=missing

  # Шаг 2: вызов deployer'а
  conan install --requires=grpc/1.60.1 \
      -pr:h=astra-gcc -pr:b=astra-gcc --no-remote \
      -o "*/*:shared=False" \
      --deployer=extensions/deployers/legacy_nupkg.py \
      --deployer-folder=output/
  
  --deployer-folder — куда сложить .nupkg. Каждый dep из install-графа → один .nupkg. Для grpc-tree выйдет 7 .nupkg (grpc + 6 transitive).

  5 важных моментов помнить
  
  1. Запускать после Release И Debug уже в cache. Без обоих — deployer ругнётся «package not in cache».
  2. Slot-tag в имени ≠ свойство контента. Контент всегда .a (static). Tag это runtime-CRT selector для downstream-резолвера.
  3. Aliases — symlinks, не копии. Старый код -lz работает, новый -lzlib тоже. 
  4. _dependencies в CMakeLists.var и .nuspec — синхронизированы. Версии и имена идентичны во всех файлах.
  5. Output полностью детерминирован. Тот же conan-cache + тот же deployer = bit-identical .nupkg.

  legacy_nupkg.py — это переводчик из Conan-формата в .nupkg-формат старого TC. Главное что он умеет:
  1. Переименовать пакет/версию под legacy-схему
  2. Уложить файлы в правильную внутреннюю структуру
  3. Сгенерить CMakeLists.var с deps в legacy-нотации
